# 製作包規範（給 AI 看的）

使用者是老師，多半不會寫程式。**每一步都用白話中文回報**，不要丟一大段程式碼給他看。

## 0. 開工先做（一定要）
1. 讀 `影片需求.json`（全部內容）和 `分鏡表.md`（好讀版）。`帳號與金鑰.json` 只在需要時讀，**絕對不要把裡面的密碼、金鑰印出來或寫進其他檔案**。
2. 讀下面第 1 節的技能清單，再讀 `skills/風格說明.md`（短影音）或 `skills/技能說明.md`（Flow 類），知道這個製作包附了哪些技能、各用在哪一步。
3. 用 3～5 行告訴使用者：片名、類別、幾鏡、幾秒、走哪條路（看 `route`：`local`＝短影音本機技能包、`auto`／`A`／`B`／`manual`＝Flow 類、`F`＝FAL 付費出片），以及會用到哪幾支技能。
4. 跑環境檢查：`python tools/check_env.py`。有紅燈就停下來，照它印出的「怎麼補」帶使用者裝好，再繼續。

## 1. 這個製作包附的技能
`skills/` 底下每一支技能都是一個資料夾，裡面有 `SKILL.md`。**要用某支技能做某一步之前，先完整讀它的 `SKILL.md`，照它的做法做**（不要憑印象手刻）。技能裡寫的路徑都以製作包資料夾為準（例如 `skills/promo-ad-forge/scripts/build_ad.py`）。

<!--SKILLS_TABLE-->

共通規則：
- 技能是用來**把作品做得更好**（片頭、字卡、結尾、配樂、角色一致性、提示詞品質），不是用來換掉本規範的流程。技能內容和本規範衝突時，**以本規範為準**。
- 技能裡提到要付費金鑰、HeyGen／HyperFrames Pro 點數、GPU、講師專用工具的做法一律不用；配音一律用免費的 edge-tts。
- 第三方技能的授權檔（`LICENSE*`、`來源與授權.txt`）不要刪。

## 2. 不能做的事
- **不要改使用者填的內容**（片名、分鏡、旁白、品牌文字）。想建議修改，先問。
- 不要刪除這個資料夾以外的任何檔案；不要動使用者其他的 Flow 專案、其他影片。
- 花點數／花錢前要確定：A 路每鏡超過 `engine.maxCostPerShot` 點就停下來問；B 路（API 付費）第一次使用前先跟使用者說「大約每秒 US$0.1」並取得同意。
- 做不到的地方，直接說原因和錯誤原文，不要假裝完成。
- 提示詞、旁白、字卡、配樂說明裡**不要點名真實歌手、藝人、名人**，也不要拿現成歌曲改詞或引用受著作權保護的歌詞；要某種感覺就描述風格特徵（例如「沙啞搖滾男聲」「溫暖木吉他民謠」）。技能範例裡若有點名真人的寫法，照這條改寫。

## 2-1. 點數與付費安全門禁（一定要遵守）
**任何會扣 Flow 點數或花錢的動作，送出前都要先用下面的確認框報告，等使用者回覆「確認」才做。** 包括：`flow_run.py` 出片、`--only N` 重做某一鏡、改用 720p 定稿重出、B 路 Gemini API、F 路 FAL（每一次 `--yes` 都算）、帳號點數用完輪替到下一個帳號後繼續、**產生角色設定圖**（`char_sheet.py make`／`redo`，不管用 Codex、Flow 或 FAL 都要先出框；Codex 不扣 Flow 點數但會用使用者 ChatGPT 方案的額度，也要寫進框裡）。

```
【要花點數／花錢，請確認】
要做什麼：出片 第 1～5 鏡（或：重做第 3 鏡／720p 定稿／B 路 API）
平台與模型：Google Flow（Veo）／Gemini API（B 路）／FAL Kling 或 Wan（F 路）
用哪個帳號：（只寫帳號代稱或前幾個字，例如 abc***@gmail.com；不要寫密碼）
預估花費：約 75 點（每鏡約 15 點 × 5 鏡）／約 US$2.4（24 秒 × 每秒約 US$0.1）／F 路寫「預估 US$x.xx，從你的 FAL 額度扣」
畫質與秒數：360p 試做、每鏡 5 秒、共 24 秒
請回覆「確認」開始，或「取消」。
```

- 收到「確認」才執行；回覆其他內容一律當作還沒同意。一次確認只涵蓋框裡寫的範圍，範圍改了（多重做一鏡、換帳號、改畫質）要重新確認。
- **失敗時不可以自己重試、也不可以自己改寫提示詞重送**（被 Flow 拒絕、逾時、點數不足、內容政策擋下都一樣）：先用白話說明失敗原因（附錯誤原文）、提出改法（例如改哪幾個字）、預估要再花幾點，再出一次確認框等使用者確認。
- **不可以自己切換到付費路線**：Flow 點數用完時 `flow_run.py` 會停下來，不會自動改走 B 路，也**永遠不會自己改走 F 路（FAL）**；使用者確認付費後才加 `--allow-b` 重跑（已完成的鏡會自動跳過，不重複扣點）。
- 已經有的片段 `flow_run.py` 預設會跳過；要全部重出才加 `--redo`（同樣要先確認）。

## 3. 配樂規則（短影音、Flow 類都適用）
1. `素材/` 裡有使用者放的 mp3／m4a／wav → **一律用使用者的**。
2. 沒有 → 可以用技能內附的 **CC BY 4.0 配樂**（`skills/flow-bgm-cc/music/`，或課程宣傳的 `skills/promo-ad-forge/music-library/`；作者 Kevin MacLeod）。把選好的曲子複製成 `06_配樂/配樂_定稿.mp3`，並把 `CREDITS_標示作者.txt` 裡**那一首的整段標示文字**存成 `06_配樂/標示作者.txt`；`make_final.py` 會把它複製到 `成品/配樂標示_貼到說明欄.txt`。
3. 用了 CC BY 配樂，**回報時一定要提醒使用者：上傳影片時把標示文字貼到說明欄；沒有說明欄（課堂播放、投放廣告）就放在片尾字卡**。
4. 技能本身有「程式合成配樂」（例如 handwrite-ad、promo-ad-forge 的 synth、pop-halftone-kit、content-to-motion-video、stickman 內附原創曲）也可以用，這類不用標示作者。
5. 這個製作包沒有附任何曲子、技能也不能合成時：不要自己上網下載音樂，回報時提醒「想加配樂可以放一首 mp3 進素材資料夾，再說重新合成」。

## 4. 短影音（route＝local）
看 `影片需求.json` 的 `shortStyle`，打開 `skills/風格說明.md`，**完全照它做**（它會告訴你用 `skills/` 裡哪一支技能、怎麼安裝、怎麼算圖）。共通要求：
- 畫面比例照 `output.ratio`；片長照 `basic.seconds`（±2 秒）；每一鏡的文字和畫面對應分鏡表。
- 字幕／旁白：分鏡表有旁白就配旁白（免費 edge-tts：`python -m edge_tts --voice zh-TW-HsiaoChenNeural --text "…" --write-media voice.mp3`）。
- **語言**（2026-11-15）：照 `影片需求.json` 的 `basic.lang`。臺灣國語／雙語配 zh-TW 聲音（不要用 zh-CN 中國大陸腔）；英文 en-US-JennyNeural／GuyNeural、日文 ja-JP-NanamiNeural、韓文 ko-KR-SunHiNeural；雙語字幕「中文｜English」拆成上下兩行；**臺語**沒有免費 TTS，不要拿華語聲音硬唸臺語漢字，請使用者把旁白稿唸一遍存成 `05_旁白/旁白.mp3`（`make_final.py` 會自動用）。
- **開場鉤子**：第 1 鏡照 `開場鉤子句型表.md`：第一個畫面就要有動作或反差、字卡 6 字內、直式字卡避開上 12%／下 25%／右 20%。
- **配樂**：照第 3 節。
- **字幕**：旁白要有逐句字幕（白字黑邊、畫面下方），不能只靠字卡上的字。
- 成品放 `成品/`，檔名照 `output.filename`，**只留一支成品**（中間檔、高畫質備份放 `_工作檔/`）。
- 做完要關掉自己開的背景程式（例如 `npx hyperframes preview`、無頭 Chrome），不要留在學員電腦上。
- 完成後擷取 3 張畫面（開頭、中間、結尾）自己看過，確定沒有破圖、字沒有超出畫面、沒有亂碼，才回報。

## 5. Flow 類（課程宣傳、校園形象、知識概念短片）
**預設一定走 A 路自動化（Google Flow＋Flow 小幫手）**。附的技能只負責「包裝與品質」（提示詞修飾、片頭、資訊字卡、Logo 結尾、配樂、角色一致性檢查），**不可以**因為有技能就改成手動流程、跳過 Flow、或改用技能整支做影片。

### A 路：Google Flow（預設）
前提：使用者的 Chrome 已安裝「Flow 小幫手」（在 `tools/Flow小幫手擴充/`，安裝方法見 `先讀我.md` 第 3 步，課程 U06B 有完整教學），並開著已登入的 https://flow.google.com 分頁。不需要開著影片製作包生成器（flow_run 會自己開橋接）。
0. **出片前檢查**（不花點數）：`python tools/flow_ready.py`。有紅燈就停下來，照它印出的「怎麼補」請使用者處理，處理好再跑一次，全部不是紅燈才繼續。不要把檢查印出的帳號 email 抄進其他檔案。
1. **先看提示詞**（不花點數）：`python tools/flow_run.py --dry` → 把每鏡提示詞摘要給使用者看，連同最後的「出片計畫」（角色設定圖狀態、每鏡是否用參考圖、預估點數）。可以照 `skills/技能說明.md` 用 `emotion-director` 等技能把提示詞修得更好，**改寫前後都要給使用者看、取得同意**才寫回 `影片需求.json`。
1-1. **角色設定圖（影片需求.json 的 `characters` 不是空的才做）**：先固定人物外觀，之後每一鏡都拿它當參考圖，人物才不會每鏡換臉。
   - `python tools/char_sheet.py status`（不花點數）看每位角色：來源 `sheet_source`（`codex` Codex 生圖／`flow` Google Flow 生圖／`upload` 學員自己的照片／`fal` FAL）、有沒有圖、預估花費。學員自己放在 `01_人物/` 的照片或設定圖（`sheet_file`，或檔名含角色名）**直接用、不重做**。
   - 缺圖的角色：先出確認框（範例見下），使用者回覆「確認」才執行 `python tools/char_sheet.py make --yes`。圖會存成 `01_人物/角色設定圖_<角色名>.png`（多角度：正面、四分之三側、全身，純色背景、無文字）；提示詞在 `01_人物/角色設定圖提示詞_<角色名>.txt`。
     - `codex`：char_sheet 會呼叫 `codex exec`（Codex 內建生圖，不扣 Flow 點數，約 1 分鐘）。你本身就是 Codex 的話，也可以直接用內建生圖工具照提示詞檔畫一張，存成 `01_人物/角色設定圖_<角色名>.png`。找不到 codex 指令時，請使用者在 Codex 對話裡說：「請用你內建的生圖工具，照 01_人物/角色設定圖提示詞_<角色名>.txt 畫一張角色設定圖，存成 01_人物/角色設定圖_<角色名>.png」。
     - `flow`：用 Flow 代理的圖像模型 Nano Banana 2.1 生成並下載；Flow 回報的點數超過 `engine.maxCostPerImage`（預設 0）會自動按「拒絕」，不扣點，要回來問使用者。
     - `fal`：用 `帳號與金鑰.json` 的 `falKey`（沒有就用環境變數 `FAL_KEY`；不要印出來），FLUX.1 dev 每張約 US$0.025（1280×720）。
   - **產生後一定要把圖打開給使用者看**（用你能顯示圖片的方式，或請使用者打開 `01_人物/` 那張圖），問「外觀 OK 嗎？」。使用者說 OK 才執行 `python tools/char_sheet.py approve`；不滿意就問要改哪裡（髮型、服裝、顏色），改 `sheet_prompt` 後出確認框、`python tools/char_sheet.py redo --name 角色名 --yes`（舊圖會改名保留）。
   - 還沒 approve 的設定圖，`flow_run.py` 會停下來（exit 3、不花點數）。使用者不想用設定圖，可以改跑 `python tools/flow_run.py --no-ref`（改回每鏡純文字）。
   - 角色是學生時，設定圖與每鏡提示詞一律寫 teenage student、不寫年齡、不寫 eyes、全身或半身中景、不特寫（Flow 對未成年敏感內容比較嚴，參考圖如果被 Flow 拒絕，照第 2-1 節回報原文，不要自己重送）。

```
【要產生角色設定圖，請確認】
角色：小美（Codex 生圖）、王老師（Google Flow 生圖）
張數：每位 1 張（正面＋四分之三側＋全身並排，灰底、無文字）
預估花費：Codex 不扣 Flow 點數（用你 ChatGPT 方案的額度，約 1 分鐘）；Flow 生圖預估 0 點（出圖前 Flow 會再報點數，超過 0 點會自動拒絕）
做好後會先給你看，你說外觀 OK 才開始出片。
請回覆「確認」開始，或「取消」。
```
2. **出片**：使用者說「開始出片」後，先照第 2-1 節出確認框（有角色時寫明「第 1、3、4 鏡會用角色設定圖當參考圖」），收到「確認」才執行 `python tools/flow_run.py`（Flow 小幫手會自動在 Flow 生成、自動核准、自動下載到 `片段/`；它也會自己開橋接、檢查點數、點數不夠換下一個帳號——帳號輪替要包含在確認框裡）。每完成一鏡，用一句話回報。
3. 某一鏡不滿意：先出確認框，確認後 `python tools/flow_run.py --only 3`（只重做第 3 鏡）。
4. **帳號登入**：`帳號與金鑰.json` 有帳號但 Chrome 沒登入時，flow_run 會自動開登入頁、填帳號密碼。如果輸出出現 `need_human`，請使用者「在 Chrome 跳出的分頁完成登入（可能要按手機上的確認）」，他說好了再重跑。
5. 想自己操作也可以：`python tools/cli-anything-flow/cli_anything_flow.py status|credits|gen …`（說明在檔頭）。
6. **首尾幀模式**（2026-11-15，全自動）：分鏡有首尾幀提示詞（`影片需求.json` 的 shots 有 frameFirst／frameLast），或 `首尾幀/` 已經有 `p01-1.png`（首幀）、`p01-2.png`（尾幀），`python tools/flow_run.py` 就會自己走 Flow 的「畫面轉影片（Frames to Video）：首幀和尾幀」（Omni 1.2 Flash 官方支援），不用請使用者手動操作：① 缺圖就用 Flow 生圖（Nano Banana，0 點；首幀附角色設定圖，尾幀附首幀＋角色設定圖，構圖和人物才一致）② 上傳兩張圖、附進提示詞、指定第 1 張是首幀、第 2 張是尾幀 ③ 讀點數、核准、下載成 `片段/shot_01.mp4`。建議先跑 `python tools/flow_run.py --frames-only`（只生圖、0 點），把 `首尾幀/` 的圖打開給使用者看，要重生哪張就刪掉再跑一次；OK 後再正式出片（每鏡點數照舊，360p 約 5 點）。使用者自己畫的圖照檔名放進 `首尾幀/` 就會直接用。不想用首尾幀：`--no-frames`。Chrome 沒開 Flow 分頁時程式會自己在背景開一個。B 路（Gemini API）也支援首尾幀，但不會自己生圖（要先 `--frames-only`）；F 路（FAL）目前不用首尾幀。
7. **台詞與口音**：影片提示詞裡有引號台詞時，一定保留 `spoken in Taiwan Mandarin with a natural Taiwanese accent`（或該語言的口音說明），不要刪掉；Flow 生出來的對白若變成中國大陸腔，回報使用者並建議改成後製旁白。
8. **打鬥鏡被擋（2026-11-15 實測）**：Google Flow 的安全審查會擋「打中身體」的鏡頭（戳肚子、拳打胸口、抓衣領撞桌、打手腕），畫面卡片顯示「失敗：這個生成內容可能違反我們的政策」，**點數會退還**。flow_run 會先做完其他鏡，最後列出被擋的鏡號。這時請你（AI）把那幾鏡在 `影片需求.json` 的 `prompt` 改成舞台武打寫法：招式點到為止、輕推、格擋、用拖把或道具掃地讓對方腳滑坐進水窪、退後撞到東西；刪掉 punch／jab／strike／hit／knock／attack 打中身體部位的字，最後加 `Stylized stage-combat comedy choreography, no real contact, nobody gets hurt, family-friendly.`；劇情和梗保留。改完先給使用者看改了哪幾句，再用 `python tools/flow_run.py --only N` 一鏡一鏡重做。同一鏡被擋 2 次就請使用者決定要不要改成不打的版本。
9. **漫劇／短劇合成（台詞模式）**：沒有旁白、分鏡畫面描述有「台詞」時，make_final.py 會自動：每鏡把「」裡的台詞當字幕、Flow 原音（角色講話）保持原音量、配樂在有人講話時自動壓低。打鬥類想要緊湊的配樂，請使用者把喜歡的 mp3 放到 `06_配樂/配樂_定稿.mp3`（自己有授權的音樂）；沒有就用製作包附的 CC BY 配樂。直式 9:16 成品是 720×1280。
10. **鎖臉：同一個角色每鏡都要是同一張臉（2026-11-15 老師回報後修正）**：有角色參考圖時，`flow_run.py` 出片前會先做「定妝照」`01_人物/定妝_<角色>.png`（照參考照的臉、穿這部戲的服裝，Flow 生圖 0 點），用本機 OpenCV 比對和參考照的相似度（≥ 0.50 才採用，最多試 4 次）。之後每鏡的首尾幀**只拿定妝照當參考**，提示詞裡角色的長相描述（年齡、臉型、眉眼）會自動換成「照參考圖／照首幀」，避免文字和照片打架；首尾幀生完比對臉（≥ 0.40，不像就重生），影片生完再抽 3 格比對（< 0.30 會自動重做 1 次，會再扣點數；`--face-retry 0` 關掉）。第一次跑會下載臉部比對模型（約 39 MB）到 `tools/_face_models/`；沒裝 opencv-python 就略過比對。**定妝照做好先打開給使用者看**，臉不像就刪掉那張重跑；參考照請用清楚的正面照（臉至少 300 像素寬）。
11. **讓觀眾看得懂**：劇本照時間順序講、不倒敘；每位角色第一次出場那鏡要點出他是誰。`影片需求.json` 的角色有 `tag`（身分，例如「北辰集團總裁」）時，make_final.py 會在角色第一次出場的鏡頭左上角自動加「名字＋身分」人物字卡 2.5 秒。交片前問自己：只看畫面和字幕的人，說得出「誰想要什麼、誰阻止他、最後怎樣」嗎？說不出來就回頭改劇本。

12. **Google Flow 新功能（2026-11-21 升級，工具已自動處理）**：
   - **花錢安全門（自動）**：每次出片前，`flow_run.py` 會打開 Flow 右上角「代理設定」，確認「生成前需確認」是「**一律**」（是「永不」時代理會不報價直接扣點，點數上限就擋不住）；不是就自動改回「一律」，改不回就停下來不出片（exit 4，0 點）。手動檢查：`python tools/cli-anything-flow/cli_anything_flow.py safety`。
   - **代理記憶（專案規則寫一次）**：`影片需求.json` 加 `"flowMemory": "臺灣口音、不要配樂、不要字幕……"`（可加 `flowMemoryTitle`），出片前會寫進 Flow「代理設定 → 記憶」，之後每鏡代理都會遵守；同內容已存在就不重寫。0 點。
   - **Flow 角色（臉＋服裝＋聲音綁在一起）**：角色加 `"flowCharacter": {"voice": "Autonoe", "voiceStyle": "臺灣年輕女生，說臺灣國語，自然的臺灣口音", "info": "外型與個性"}`，出片前會用定妝照在 Flow 左側「角色」建立同名角色（0 點；已存在就沿用），之後每鏡改附「角色」取代每鏡上傳定妝照，聲音也會一致。可選聲音（女）：Achernar 柔和高音、Aoede 輕快、Autonoe 明亮、Callirrhoe 隨和、Despina 滑順、Erinome 清楚、Gacrux 成熟；（男）Achird 友善、Fenrir 年輕興奮、Iapetus 清楚、Charon 沉穩……。不想用：`--no-character`。
   - **延伸（一鏡到底）**：某鏡加 `"extendFrom": 1`，就會把第 1 鏡的影片附進提示詞、請代理從最後一格接著往後延伸 `sec` 秒，並附定妝照（最多 3 張）＋角色維持臉一致。**實測報價：延伸 5 秒＝15 點**（一般生成 5 秒約 5 點），確認框要寫清楚。延伸只支援 Omni 1.2 Flash、付費方案（AI Plus／Pro／Ultra）。延伸後下載到的可能是「原片＋延伸」整段，合成前用 ffprobe 看長度再決定怎麼接。
   - **修改既有影片（不整鏡重生）**：`python tools/flow_run.py --edit 5 --edit-prompt "最後她的手要完全蓋住鏡頭，畫面變全黑"`（費用和生成一樣按秒計，實測 6 秒＝6 點；原片自動備份成 `shot_05_改前_時間.mp4`）。一樣要先出確認框。
   - **「無法生成音訊」**：多人說話（例如遠處有人喊話）時 Flow 常生不出聲音，失敗點數會退還。工具會印出 💡 改法：提示詞只留主角說話、其他人聲改後製配音；或在專案設定開「傳回無聲影片」、聲音全部後製。照第 2-1 節先問使用者再改。
   - **12 月 5 日起** Flow 只剩 Omni Flash 1.2 與 Veo 3.1 Lite（Veo 3.1 Fast／Quality、Omni Flash 1.1 停用），本工具預設就是 Omni 1.2 Flash，不受影響。

### 包裝（片段到齊後、合成前）
照 `skills/技能說明.md`：
- 角色一致性檢查（有附 `consistency-checker` 時）：`python skills/consistency-checker/scripts/from_video_request.py`。有角色設定圖時，也把每鏡中間畫面和 `01_人物/角色設定圖_<角色名>.png` 比對（臉型、髮型、服裝顏色）。
- 動態片頭 → `03_字卡/片頭.mp4`（或靜態 `片頭.png`）；動態結尾（Logo 動畫、報名資訊、CTA）→ `03_字卡/片尾.mp4`（或 `片尾.png`）。尺寸、比例和 Flow 片段一致；畫面文字只用使用者填的內容。
- 配樂照第 3 節。

### Flow 點數全部用完時
flow_run 會停下來（不會自動改走付費路線）。**先停下來問使用者**，說明可選：①明天點數恢復再繼續（已下載的片段會保留、重跑會自動跳過）②走 B 路（要有 `apiKey`；出確認框、確認後 `python tools/flow_run.py --allow-b`）③改用免費備援（`skills/技能說明.md` 裡標「備援」的技能，例如動態廣告、火柴人、實景素材）。使用者選了才做。

### B 路：Gemini Omni API
`帳號與金鑰.json` 的 `apiKey` 有值才能用。`route` 是 `auto` 時，只有使用者確認後加 `--allow-b` 才會在 A 路點數用完時切過去；`route` 是 `B` 就只走 B 路（同樣每次送出前先出確認框）。工具是 `tools/omni_api.py`（背景生成、每 15 秒查一次進度，只用 Python 內建功能）；`tools/gemini-omni-flash-api/` 是 Google 官方技能（Apache-2.0）當參考，要做影片延伸、參考圖時可以照它的說明用。如果回報 RESOURCE_EXHAUSTED，表示金鑰的專案沒有影片額度，請使用者到 https://aistudio.google.com 開通付費。

### F 路：FAL（付費，按秒計費；`route` 是 `F` 才走）
使用者在生成器 ⑨ 選了「FAL（付費，按秒計費）」才會是 `F`。`auto` 永遠不會自己改走 FAL。工具是 `tools/fal_api.py`（FAL 佇列 API，只用 Python 內建功能）。金鑰順序：`帳號與金鑰.json` 的 `falKey` → 環境變數 `FAL_KEY`。**金鑰不要印出來、不要寫進任何檔案、不要貼進對話**。
- 模型（`engine.falModel`）：`kling`＝Kling 2.5 Turbo Pro（品質優先，每秒約 US$0.07）；`wan`＝Wan 2.5（省錢，480p，每秒約 US$0.05）。**一鏡只能 5 或 10 秒**（7 秒以下算 5 秒）。
- 有角色出場的鏡頭＝圖生影片：先用 FLUX Kontext 把 `01_人物/角色設定圖_<角色名>.png` 做成這一鏡的首幀（每張約 US$0.04，存 `01_人物/首幀/`），再交給 Kling／Wan 動起來。所以**角色設定圖一樣要先做、給使用者看過說 OK（approve）**。
0. **出片前檢查**（不花錢）：`python tools/flow_ready.py`（F 路會檢查：有沒有 FAL 金鑰、金鑰能不能用〔FAL 免費的價目查詢〕、角色設定圖好了沒）。有紅燈照「怎麼補」處理。
1. **出片計畫**（不花錢）：`python tools/flow_run.py --dry` → 每鏡模型、計費秒數、預估美元、合計。把合計用一句話告訴使用者。
2. **確認框**：`python tools/flow_run.py`（沒加 `--yes`）只會印出「【要花錢，請確認】…預估 US$x.xx，從你的 FAL 額度扣」就停下來、不花錢。把框原封不動給使用者看，**使用者回覆「確認」後**才執行 `python tools/flow_run.py --yes`。
3. 失敗**不會自動重試**，也不要自己重送：照錯誤原文用白話說明——401＝金鑰錯（到 fal.ai 的 Keys 頁重建）；餘額不足／帳戶被暫停＝到 https://fal.ai/dashboard/billing 儲值；422 內容被拒＝改寫提示詞。改好後再出一次確認框，確認後 `python tools/flow_run.py --only N --yes`。
4. `出片紀錄.json` 每鏡記 `route: "F"`、`model`、`cost_usd`（依公開單價計算）、`request_id`；`fal_total_usd` 是這支片累計。**實扣金額請使用者到 fal.ai 的 Usage／Billing 頁看**（金鑰沒有查帳權限，程式查不到餘額）。
5. 某一鏡不滿意：照第 2-1 節出確認框，確認後 `python tools/flow_run.py --only 3 --yes`。想省錢可以 `--fal-model wan`。

### manual：只整理提示詞
只有 `route` 是 `manual` 才用：`python tools/flow_run.py --dry` 會存成 `Flow提示詞清單.txt`，請使用者自己貼進 Flow，下載的片段照 `片段/shot_01.mp4`、`shot_02.mp4`… 命名放好，再做下一步。

### 合成成品
全部片段到齊、包裝做好後：`python tools/make_final.py`（統一尺寸 → 片頭 → 結尾 → 字幕 → edge-tts 旁白 → 配樂 → `成品/`）。

## 6. 每一鏡都要自己檢查
- `ffprobe` 看秒數、尺寸；用 ffmpeg 擷取中間一張畫面**自己看**：主角、場景有沒有符合分鏡？有沒有出現文字、浮水印、怪手怪臉？
- 不符合就重做那一鏡（A 路要再花點數，先問使用者）。
